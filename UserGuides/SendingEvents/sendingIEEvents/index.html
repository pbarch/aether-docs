Connecting External Tools¶

This guide explains how to inject Influence Engine events into Aether from any tool that can send OSC UDP — Python scripts, microcontrollers (CircuitPython, MicroPython), Max MSP patches, and similar.

Typical use cases: - A microcontroller reading a radar sensor and emitting createPresence events at detected positions - A Max MSP patch that responds to audio energy by triggering createPulse events - A Python script driving pheromone trails from algorithmic or generative data

Network Setup¶

Each Node Controller (NC) listens directly for OSC on UDP port 1212. Events must be sent to the broadcast address of your subnet — either 255.255.255.255 (global broadcast) or the subnet broadcast address (e.g. 192.168.1.255). This is what ensures all NCs on the network receive the event simultaneously.

Do not send to the server's IP address for normal use — the server does not forward events to the NCs. Sending to the server IP will reach the server only, not the NCs.

Your sending machine must be on the same subnet as the NCs.

Exception — recording sessions:

If you need the server to capture events for replay during a performance recording, send to the server's IP address using the path /server/<EngineName>/sendEvent. The server logs the event and rebroadcasts it to all NCs. All other message details are identical. This is only needed when recording.

OSC Message Format¶

Every event follows this structure:

OSC address: /<EngineName>/sendEvent

Arguments: 1. eventName — string — the name of the event

  1. Repeated key–value pairs:
  2. paramName — string
  3. paramValue — int or float (type matters — see each engine's table below)

All positions for Influence Engine events are in World Space millimetres. You can find the world-space coordinates of a Node by right-clicking on it in the Dashboard plan. For details on how Aether's World Space coordinates are oriented see the Coordinate Spaces

RadiantPulse — createPulse¶

A radiant pulse is an expanding ring (or sphere) that propagates outward from a point and fades over its lifespan. Pulses accumulate: multiple simultaneous pulses sum at each location, clamped to 0–1.

OSC address: /RadiantPulse/sendEvent Event name: createPulse

Parameter Type Unit Default Range Description
x int mm (required) — Origin X
y int mm (required) — Origin Y
z int mm (required) — Origin Z
core int mm 100 — Radius of the solid inner core
size int mm 600 100–1500 Outer radius at emission
speed float m/s 1.5 0–3 Expansion speed
lifespan int ms 4500 50–5000 Time until the pulse is removed
strength float 0–1 0.8 0–1 Peak influence
fadeRatio float 0–1 0.7 0–1 Fraction of lifespan spent fading
spherical int 0/1 1 — 1 = 3D sphere, 0 = planar ring

x, y, z are required. Omitted optional parameters fall back to the NC's current RadiantPulse settings.

Presence — createPresence¶

A presence event places a Gaussian influence field at a point. Fields from multiple events sum together and fade individually. The influence vector points radially outward from each event's position — actuators are pushed away from detected presences.

OSC address: /Presence/sendEvent Event name: createPresence

Parameter Type Unit Default Range Description
x int mm (required) — Centre X
y int mm (required) — Centre Y
z int mm (required) — Centre Z
sigma float mm 400 50–3000 Gaussian spread (standard deviation)
strength float 0–1 0.8 0–1 Peak influence at centre
lifespan int ms 3000 100–10000 Time until the field is removed
fadeRatio float 0–1 0.5 0–1 Fraction of lifespan spent fading
spherical int 0/1 0 — 1 = 3D Gaussian falloff, 0 = planar

For a person-tracking use case, send one event per detected person per sensor frame (e.g. at 10 Hz for the LD2450 radar). With lifespan = 3000ms and fadeRatio = 0.5, a presence field lingers 1.5 seconds after the person leaves the frame.

Pheromone — createPheromone¶

A pheromone event places a Gaussian field that can attract actuators toward the source or repel them away. Pheromone trails accumulate naturally when events are sent at a position repeatedly — they are long-lived by design.

The influence vector points toward the event position for positive (attracting) pheromones, and away for negative (repelling) ones.

OSC address: /Pheromone/sendEvent Event name: createPheromone

Parameter Type Unit Default Range Description
x int mm (required) — Centre X
y int mm (required) — Centre Y
z int mm (required) — Centre Z
sigma float mm 600 50–3000 Gaussian spread
strength float 0–0.5 0.05 0–0.5 Influence magnitude
positive int 0/1 1 — 1 = attracting (toward source), 0 = repelling
lifespan int ms 10000 100–30000 Time until the field is removed
fadeRatio float 0–1 0.3 0–1 Fraction of lifespan spent fading
spherical int 0/1 0 — 1 = 3D falloff, 0 = planar

strength is always a positive magnitude (0–0.5); the direction of effect is set by positive. Low strength values (0.05–0.1) work well for trails because fields accumulate with each event sent.

Python Examples¶

Install python-osc:

pip install python-osc

One-shot events¶

from pythonosc.udp_client import SimpleUDPClient

# Broadcast to all NCs on the network
client = SimpleUDPClient("255.255.255.255", 1212, allow_broadcast=True)

# RadiantPulse
client.send_message("/RadiantPulse/sendEvent", [
    "createPulse",
    "x",         1500,
    "y",         2000,
    "z",         0,
    "size",      800,
    "speed",     1.5,
    "lifespan",  4500,
    "strength",  0.8,
    "fadeRatio", 0.7,
    "spherical", 1,
])

# Presence
client.send_message("/Presence/sendEvent", [
    "createPresence",
    "x",         3200,
    "y",         1100,
    "z",         900,
    "sigma",     400.0,
    "strength",  0.8,
    "lifespan",  3000,
    "fadeRatio", 0.5,
    "spherical", 0,
])

# Pheromone (attracting trail)
client.send_message("/Pheromone/sendEvent", [
    "createPheromone",
    "x",         2000,
    "y",         1500,
    "z",         0,
    "sigma",     600.0,
    "strength",  0.1,
    "positive",  1,
    "lifespan",  10000,
    "fadeRatio", 0.3,
    "spherical", 0,
])

Type notes: python-osc infers OSC types from Python types: int → OSC integer, float → OSC float, str → OSC string. Write 400.0 not 400 for float parameters, and use plain int values for x, y, z, lifespan, spherical, and positive.

Continuous presence tracking loop¶

This pattern fits a sensor that reports detected positions at a fixed rate (e.g. an LD2450 radar at 10 Hz):

import time
from pythonosc.udp_client import SimpleUDPClient

client = SimpleUDPClient("255.255.255.255", 1212, allow_broadcast=True)

SENSOR_HEIGHT_MM = 900  # Z height of detected persons

while True:
    targets = read_sensor()  # returns list of (x_mm, y_mm) in LASD world space

    for x, y in targets:
        client.send_message("/Presence/sendEvent", [
            "createPresence",
            "x",         int(x),
            "y",         int(y),
            "z",         SENSOR_HEIGHT_MM,
            "sigma",     400.0,
            "strength",  0.8,
            "lifespan",  3000,
            "fadeRatio", 0.5,
            "spherical", 0,
        ])

    time.sleep(0.1)  # 10 Hz

Pheromone trail from a moving object¶

Dropping pheromone events at each position in a path builds a trail. With low strength and long lifespan, the trail accumulates and fades slowly:

for x, y in path_positions:
    client.send_message("/Pheromone/sendEvent", [
        "createPheromone",
        "x",         int(x),
        "y",         int(y),
        "z",         0,
        "sigma",     600.0,
        "strength",  0.05,  # low — trail accumulates
        "positive",  1,
        "lifespan",  10000,
        "fadeRatio", 0.3,
        "spherical", 0,
    ])
    time.sleep(0.05)  # 20 Hz

Max MSP Examples¶

Max MSP sends OSC using [oscformat] → [udpsend].

In Max messages, an atom without a decimal is an integer; with a decimal it is a float. Parameters like speed, sigma, strength, and fadeRatio must have a decimal point (e.g. 1.5, 400., 0.8). Parameters like x, y, z, lifespan, spherical, and positive must be plain integers.

Basic patch structure¶

[message]
    |
[oscformat]
    |
[udpsend 255.255.255.255 1212]

[udpsend] must be opened with the broadcast address before use — either send it a connect 255.255.255.255 1212 message, or include it as arguments: [udpsend 255.255.255.255 1212].

RadiantPulse¶

Static message box:

/RadiantPulse/sendEvent createPulse x 1500 y 2000 z 0 size 800 speed 1.5 lifespan 4500 strength 0.8 fadeRatio 0.7 spherical 1

Presence¶

Static message box:

/Presence/sendEvent createPresence x 3200 y 1100 z 900 sigma 400. strength 0.8 lifespan 3000 fadeRatio 0.5 spherical 0

[screenshot — static Presence patch]

For a dynamic patch where position comes from number boxes or a tracking source, use [sprintf] to substitute x, y, z at send time:

[number x] [number y] [number z]

Connect these to the inlets of:

[sprintf /Presence/sendEvent createPresence x %i y %i z %i sigma 400. strength 0.8 lifespan 3000 fadeRatio 0.5 spherical 0]

The %i specifiers keep the substituted values as integers. The fixed float parameters (400., 0.8, etc.) remain as float atoms in the output list.

[screenshot — dynamic Presence patch with number boxes and sprintf]

Pheromone¶

Static message box (attracting):

/Pheromone/sendEvent createPheromone x 2000 y 1500 z 0 sigma 600. strength 0.1 positive 1 lifespan 10000 fadeRatio 0.3 spherical 0

To toggle between attracting and repelling, route a [toggle] into a [select 0 1] → two message boxes:

/Pheromone/sendEvent createPheromone x 2000 y 1500 z 0 sigma 600. strength 0.1 positive 1 lifespan 10000 fadeRatio 0.3 spherical 0
/Pheromone/sendEvent createPheromone x 2000 y 1500 z 0 sigma 600. strength 0.1 positive 0 lifespan 10000 fadeRatio 0.3 spherical 0
